================================================================================
                           1. DESCRIPTION DU PROJET
================================================================================

NOM: Light Church
TYPE: Application full-stack de gestion d'églises en France
PUBLIC: Pasteurs et administrateurs d'églises

FONCTIONNALITÉS PRINCIPALES:
- Gestion des informations d'église (nom, dénomination, localisation GPS)
- Gestion des événements religieux
- Gestion des horaires d'activités (cultes, prières, etc.)
- Gestion des réseaux sociaux de l'église
- Interface d'administration pour les pasteurs
- Application mobile React Native (prévue) pour afficher les 3000+ églises sur carte

CONTEXTE:
- Base de données contient 3000+ églises pour tester la performance
- Utilise des coordonnées GPS (POINT geometry MySQL) pour géolocalisation
- Optimisé pour afficher les églises sur une carte mobile
- Architecture morcelée: récupère d'abord les données essentielles (table churches),
  puis les détails complets sur demande (performances optimales)

================================================================================
                        3. BASE DE DONNÉES MYSQL
================================================================================

TABLES PRINCIPALES (12 au total):

1. admins
   - Utilisateurs (pasteurs) avec email/password hashé
   - Statut: PENDING → ACTIVE (validation admin)

2. churches
   - Informations principales des églises
   - location: POINT geometry (longitude, latitude)
   - Indexes: SPATIAL sur location, FULLTEXT sur church_name

3. church_details
   - Détails étendus (description, adresse, téléphone, site web, pasteur, parking)
   - Relation 1:1 avec churches

4. church_socials
   - Réseaux sociaux (FACEBOOK, INSTAGRAM, YOUTUBE, TIKTOK, WHATSAPP, LINKEDIN)
   - Relation 1:N avec churches

5. church_schedules
   - Horaires des activités
   - day_of_week: ENUM(MONDAY, TUESDAY, ..., SUNDAY)
   - start_time: TIME
   - activity_type_id: FK vers activity_types

6. events
   - Événements organisés par les églises
   - start_datetime, end_datetime
   - location: POINT geometry
   - status: PUBLISHED, CANCELLED, DRAFT, COMPLETED

7. denominations
   - Types de dénominations religieuses

8. activity_types
   - Types d'activités (Culte, Prière, Jeunesse, etc.)

DONNÉES DE TEST:
- 3008 admins créés par massiveSeedData.js
- 3007 églises avec 60 villes françaises réelles
- 6009 événements
- Coordonnées GPS réelles de villes françaises

REQUÊTES OPTIMISÉES:
- Recherche spatiale avec ST_Distance_Sphere()
- FULLTEXT search sur church_name
- Toutes les requêtes < 70ms même avec 3000+ églises

              13. AUTOCOMPLÉTION D'ADRESSE (NOUVEAU - 23 DEC 2025)
================================================================================

## 🎯 PROBLÈME RÉSOLU:
Les pasteurs pouvaient entrer n'importe quelle adresse et coordonnées GPS invalides.
Il fallait une solution GRATUITE pour valider les adresses françaises et obtenir les
coordonnées GPS automatiquement.

## ✅ SOLUTION IMPLÉMENTÉE:

### API UTILISÉE: adresse.data.gouv.fr
- API officielle du gouvernement français
- 100% GRATUITE, sans clé API
- Base de données: La Poste + IGN
- Adresses françaises réelles uniquement

### NOUVEAUX CHAMPS BASE DE DONNÉES:

Table: church_details
- street_number VARCHAR(20)     # Numéro de rue (ex: "10")
- street_name VARCHAR(255)      # Nom de rue (ex: "Rue de la Paix")
- postal_code VARCHAR(10)       # Code postal (ex: "75002")
- city VARCHAR(100)             # Ville (ex: "Paris")

Index ajoutés:
- idx_city ON church_details(city)
- idx_postal_code ON church_details(postal_code)

Migration: backend-express/migrations/add_address_fields.sql

### NOUVEAU COMPOSANT: AddressAutocomplete

Fichier: frontend-react/src/components/AddressAutocomplete.tsx

Fonctionnalités:
✅ Autocomplétion en temps réel (debounce 300ms)
✅ Liste déroulante avec suggestions d'adresses réelles
✅ Affichage ville + code postal pour chaque suggestion
✅ Auto-remplissage de TOUS les champs lors de la sélection
✅ Loading spinner pendant la recherche
✅ Message "Aucune adresse trouvée" si rien ne correspond
✅ Icône MapPin et Search pour meilleure UX

Exemple de workflow utilisateur:
1. Tape "10 Rue de la Paix"
2. L'API suggère des adresses réelles
3. Sélectionne "10 Rue de la Paix, 75002 Paris"
4. AUTO-REMPLI:
   - address: "10 Rue de la Paix, 75002 Paris"
   - street_number: "10"
   - street_name: "Rue de la Paix"
   - postal_code: "75002"
   - city: "Paris"
   - latitude: 48.8698
   - longitude: 2.3310

### VALIDATION MISE À JOUR

Frontend (Zod): frontend-react/src/lib/validationSchemas.ts
```typescript
// Nouveaux champs d'adresse
street_number: z.string().max(20).optional()
street_name: z.string().max(255).optional()
postal_code: z.string().regex(/^[0-9]{5}$/).optional()
city: z.string().min(2).max(100).optional()

// FIX: Champs optionnels ne valident que si remplis
phone: z.string().optional()
  .refine((val) => !val || /^[0-9+\s()-]{10,20}$/.test(val))

website: z.string().optional()
  .refine((val) => !val || /^https?:\/\/.+/.test(val))

parking_capacity: z.union([
  z.number().int().min(0).max(10000),
  z.null(),
  z.undefined()
]).optional().nullable()
```

Backend (express-validator): backend-express/validators/churchValidator.js
```javascript
// FIX: optional({ values: 'falsy' }) pour skip validation si vide
body('website')
  .optional({ values: 'falsy' })
  .trim()
  .isURL()

body('parking_capacity')
  .optional({ values: 'falsy' })
  .isInt({ min: 0, max: 10000 })
```
